The notehead object

Type: Dictionary

Describes the shape and glyph of a notehead. This is purely for visual purposes and doesn't in itself affect pitch, duration or performance.

Generally it's better to encode "shape" instead of "glyph", because the former is a more general concept. For example, the notehead shape "oval" is typically represented as the SMuFL glyph "noteheadHalf" for half notes, "noteheadBlack" for smaller rhythmic values, etc. Encoding "shape" instead of a hard-coded "glyph" makes the document more flexible.

In tuplets and multi-note tremolos, use the displayed note value rather than the elapsed performance duration.

For a kit note, if the notehead isn't explicitly encoded, consuming software should use the kit component's notehead instead, including its glyph.

MNX doesn't currently have a way to assign notehead shapes dynamically according to pitch or staff position, such as shape-note notation. Applications may still encode such settings using vendor extensions. When no kit-component notehead applies and the notehead object is omitted, consuming software may use those settings to choose its shape. An explicit shape, such as "oval" or "diamond", should override that setting.

Attributes

Name Type Required? Description
glyph smufl glyph No An explicit SMuFL glyph for this notehead. This overrides the glyph that a rendering engine would otherwise select.

Generally we recommend using "shape" instead of this, because "shape" retains semantics.

The presence of "smufl-glyph" has no effect on note pitch, duration or performance. It's purely visual.
shape notehead shape Yes The semantic shape family of this notehead.

As with "glyph", the presence of "shape" has no effect on note pitch, duration or performance. For example, "diamond" does not by itself specify an artificial harmonic, and "slash" does not specify pitchless notation or a beat repeat.

Plus globally available attributes: _c, _x, id
